# Forge ECC wave 2 — implementation plan

**Goal:** close the next eight improvements: green CI, automatic risky review, enforced human gates, default runtime checks, durable apprentice promotion, a guarded self-improvement bridge, load/backpressure and a live job view.

**Architecture:** five independent slices create new modules or touch only their own named files. The orchestrator owns all entry points (`external_agent.py`, `ship.py`, `orchestration.py`, `cli/main.py`, `adapters.py`, `project_adapters.py`, `apprentice_policy.py`, `ci_feedback.py`, `self_improve.py`, `concurrency.py`, `metrics.py`) and wires between waves. Keep interfaces small, accept dependencies, return results, prefer two real adapters before a seam, TDD red-green.

**Tech stack:** Python 3.12, Pydantic, pytest, Ruff, Mypy, git worktrees.

**Children:** read this plan first. Run only your own test file, then Ruff/format/Mypy on your files. Do not run the full suite in parallel. Commit on your branch; do not push, merge, deploy or edit `.env`. Report under 25 lines in plain English.

## Wave 1 — five ECC slices

1. **A08 Eval + D01 Critic** — `factory/ecc2-review`, `D:/ecc2-a1`.
   Items 2 and 3. Create `src/agency/forge/risky_review.py` (`apply_risky_review`, `RiskyReviewReport`) that automatically runs the existing `quorum.run_quorum` and `gold_set.evaluate_gold_set` for risky jobs through injected critic/run adapters, fail-closed with honest caveats. Create `src/agency/forge/gate_attestation.py` (`attest_human_gates`, `GateAttestation`) that verifies required human gates from `human_gates.required_human_gates` are named in an approval record before a merge is allowed. Test: `tests/test_forge_ecc2_review.py`. Forbidden: `external_agent.py`, `ship.py`, `approvals.py`, `orchestration.py`, `cli/main.py`.

2. **A04 Permission Warden + A06 Guardrail Author** — `factory/ecc2-runtime`, `D:/ecc2-a2`.
   Items 4 and 5. Create `src/agency/forge/runtime_specs.py` (`RuntimeSpec`, `spec_for`, two real specs for node and python) giving default verify command/endpoints per product type, with no network at import time. Create `src/agency/forge/promotion_ledger.py` (`PromotionLedger`, `record_promotion`, `is_promoted`) as a bounded durable append-only store with named approver and no generic auto-promotion. Test: `tests/test_forge_ecc2_runtime.py`. Forbidden: `adapters.py`, `project_adapters.py`, `apprentice_policy.py`, `external_agent.py`, `cli/main.py`.

3. **A09 Self-Improvement + B02 Spec Compiler** — `factory/ecc2-improve`, `D:/ecc2-a3`.
   Item 6. Create `src/agency/forge/improvement_bridge.py` (`bridge_failures`, `BridgeReport`) that takes `ci_feedback` candidates, dedupes with stable keys, and produces proposed jobs only after a named human approver; it must never dispatch, merge or push. Expose a helper the orchestrator can call from `forge learn`. Test: `tests/test_forge_ecc2_improve.py`. Forbidden: `cli/main.py`, `ci_feedback.py`, `self_improve.py`, `orchestration.py`.

4. **A01 Orchestrator + A10 Reliability** — `factory/ecc2-scale`, `D:/ecc2-a4`.
   Items 7 and 8. Create `src/agency/forge/load_harness.py` (`run_load_probe`, `LoadReport`) with bounded synthetic jobs, measured acceptance/latency and an explicit backpressure recommendation. Create `src/agency/forge/live_view.py` (`render_jobs_view`, `JobView`) presenting state, phase timings, cost, gates and stuck reasons from job records without mutating them. Test: `tests/test_forge_ecc2_scale.py`. Forbidden: `orchestration.py`, `concurrency.py`, `cli/main.py`, `metrics.py`, `observability.py`.

## Wave 2 — orchestrator wiring

Merge the five branches. Wire: risky review into `external_agent.py`; gate attestation into `ship.py`/`forge ship`; runtime specs into adapters and runtime verification; promotion ledger into apprentice dispatch; improvement bridge into `forge learn`; load harness and live view into CLI. Add parent wiring tests.

## Wave 3 — proof

Ruff, Mypy, full pytest, a real probe against the job DB, Forge pipeline on changed paths. PR, CI, then merge only when gates are green. Report plainly with real gate output and caveats.

## Non-negotiables

No secrets, no worker-side push/merge/deploy, own-branch commits, bounded timeouts, stalled jobs become `UNCERTAIN` never "success".
