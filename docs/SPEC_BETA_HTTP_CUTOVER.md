# HTTP authority cutover — default-deny checkpoint

Status: historical route inventory at `cd2afd4`; **local default-deny cutover implemented** in `b10036d` and `af7b7f4`, not deployed. Companion: `SPEC_BETA_BOUNDARY_AND_PEER_EXECUTION.md` and `SPEC_KNOWN_PEER_PROTOCOL.md`. The matrix below describes the **pre-cutover source-defined routes**, not their current reachability or proof of deployment. Telegram admission does not protect either HTTP app. The current local Agency and legacy Butler app constructors permit GET health only; Agency routers independently deny requests when mounted elsewhere. No peer-grant verifier or downstream actuator gate exists yet. An owner token alone cannot cast a peer ballot.

## Source-verified route matrix

- Agency API (`src/agency/api/server.py:143-164`): `/v1/agents` POST/DELETE/PATCH mutate identity/capabilities without authentication or grant (`routers/agents.py:89-138`). `/v1/governance/propose` and `/vote` accept a token but assert `user` provenance; the engine immediately resolves a `user` vote (`routers/governance.py:18-29,76-113`, `lattice/governance.py:143-149`). `/v1/bridges/{name}/execute` invokes a potentially side-effecting bridge without a grant (`routers/bridges.py:93-116`). `GET /v1/bridges/{name}/health` actively probes external bridges; it is not a passive read (`routers/bridges.py:120-133`). Task POST/PATCH/POST-message persist caller-asserted identity and state (`routers/tasks.py:87-171`); evidence POST persists caller-asserted provenance (`routers/evidence.py:90-101`). `/v1/memory/search` has caller-selected owner scope (`routers/memory.py:46-69`); other sensitive reads have no Agency-wide read policy.
- Separate legacy Butler HTTP app (`src/agency/butler/server.py:164-208`): unauthenticated `POST /v1/message` enters the legacy tool-capable orchestrator and open registry (`butler/service.py:390-424`, `orchestrator.py:173-195,462-502`). This cannot be made safe by Telegram-only admission. The local prototype `/api/chat` is a distinct isolated tool-free path; do not regress it or confuse loopback checks with network-wide authority.
- Telegram polling/webhook: private-chat invite checks exist in `telegram/handler.py:43-84`, but the tool-capable `/research` and ordinary Butler paths still lack principal/budget/audit propagation. The webhook secret is checked before parsing in `telegram/server.py:38-55`. Neither Telegram user nor Butler may mint a peer vote.

## Minimal safe cutover and tests

1. **Implemented locally, not deployed:** the Agency and legacy Butler app constructors deny all requests except GET `/v1/health` before body processing or downstream calls, including CORS preflights and mounted-prefix paths. All six Agency routers independently reject even if directly mounted in another FastAPI app. There is no owner-token override or `AGENCY_UNSAFE_*` beta override. This deliberately makes HTTP read and mutation routes unavailable until a separate authenticated authority implementation is reviewed.
2. Peer grant verification is a separate later implementation and must occur again at the actual identity registry, governance resolver, bridge actuator and other side-effect boundary. A router-only check is not proof of decentralization. Do not turn on consequential routes until the owner chooses a failure model and signed quorum/affected-consumer/fencing tests pass.
3. **Verified on isolated branch:** `tests/test_beta_http_cutover.py`, governance HTTP and Butler tests assert 503 for token/no token, malformed bodies, CORS preflight, mounted-prefix requests and independently mounted Agency routers, with no injected bridge call. The corrected route branch reported **938 passed** in its offline full suite, Ruff and mypy passing. This tests the deny cutover only, not a future peer-grant implementation.
4. Independent review passed this narrow local HTTP denial slice after mounted-prefix and direct-router bypasses were fixed. Re-verify the combined main revision before any future deployment; this cutover does not authorize a rollout, restart, or mutation enablement.

Open decisions: HTTP read authentication scheme, live deployment exposure, and the peer failure model/quorum are not approved. Safe default is no new beta invitees, no exposed untrusted HTTP app, and no consequential action.
